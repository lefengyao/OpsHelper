服务器运维助手 v1.13.1
========================================

一、怎么用
  1. 把整个文件夹解压到任意位置（U 盘、桌面、D 盘都行）。
  2. 双击 ServerOpsHelper.exe 启动。
  3. 首次登录用默认账号：admin / admin123
     登录后建议到「系统设置 → 账号安全」把密码改掉。

  （如果你装的是 Setup 安装包：
    · 标准的中文安装向导，一路点「下一步」就行：
      欢迎 → **选择目标位置** → 附加任务 → 准备安装 → 安装 → 完成；
    · **安装位置就在向导里直接显示**，想换盘直接改路径，或点「浏览」挑文件夹
      （v1.9.3 起换了安装程序，不再藏在「选项」按钮后面）；
    · 默认**仅安装给当前用户**（装到 %LOCALAPPDATA%\Programs\ServerOpsHelper），
      **不弹管理员权限**；已经是管理员账号时，向导第一页还会让你选
      「为所有用户安装」（装到 Program Files，需要一次授权）；
    · 开始菜单和桌面都会有快捷方式（桌面那个可以在「附加任务」里取消）；
    · 卸载走 Windows「设置 → 应用」，或者开始菜单里的「卸载 服务器运维助手」。
      Inno 的卸载程序**永远不会动你的数据目录**。）

  ★注意：不管程序装在哪，**你的数据都固定在 %LOCALAPPDATA%\ServerOpsHelper**
    （链接、密码箱、访问历史、登录账号），不跟着程序目录走 —— 见下面第三节。
    想把数据也放到别的盘，用环境变量 SERVEROPSHELPER_CONFIG_DIR 指定目录即可。

二、这个版本有什么
  · 服务器列表   记录服务器信息；点进详情就是一个完整的服务器工作台——
                 这里是**真交互式 SSH 终端**（vim / htop / Tab 补全 / 上下键历史 /
                 Ctrl+C，带颜色），下面是 **SFTP 文件管理**（浏览 / 上传 / 下载 /
                 重命名 / 新建文件夹 / 删除），左侧是 **实时监控**
                 （CPU、内存、磁盘、网络、负载，每 3 秒刷新）。
                 终端、文件、监控走三条独立连接，传大文件时终端照常能用
  · 常用链接     保存经常打开的后台网页；宝塔面板可按「IP + 端口 + 安全入口」专用录入
  · 访问记录     本次打开应用后访问过的页面 + 全部历史（最多 300 个地址，可搜索、可转存为常用链接）
  · 密码箱       集中记录账号密码，支持一键生成随机强密码、按站点自动匹配填充
                 （「填充账号密码」优先用「常用链接」里的账号密码；
                  链接里缺的那一项，会去密码箱里同站点的记录自动补上 ——
                  所以链接里只填了账号、没填密码时，也能把密码填进去）
  · Web 控制台   内置浏览器。顶部一排**标签页**，打开过的页面各占一格，点一下就能切换；
                 标签多了自动变窄、再多就横向滚动。工具栏只留「地址栏 + 打开 + ☰」，
                 其余按钮都收进 ☰ 弹出的**竖向下拉菜单**（贴着按钮弹出、点外面自动关，
                 完全不占网页空间）。菜单里的「填充后高亮输入框」开着时，自动填充后会在
                 网页里高亮闪烁被填的输入框，一眼看到填到哪了。
                 在页面里手动登录一次后，会自动询问是否把账号密码收进密码箱
  · 最近访问     在左侧导航栏最下方：点一下直接切换过去。
                 内置浏览器是常驻的，切到别的功能页只是把它折叠起来，
                 正在看的网页（连同标签）都不会丢，也不用重新输地址。
  · 智能体接入   把已保存的服务器暴露成一个 MCP 服务，本机的 AI 智能体
                 （Claude Desktop、CodeBuddy、Cline 等）接上后可以直接查询、操作这些机器。
                 服务器列表不用重新录一遍。详见第四节。
  · 扩展         自己加功能，不用等新版本：设置里装一个扩展包，就多几条命令。
                 它会出现在服务器详情页顶部的下拉框里，智能体也能直接调用。
                 内置了 Nginx 维护、系统巡检、日志排查三个现成的。详见第五节。

  · FRP 穿透     内网穿透管理：一键启停 frpc / frps、增删转发规则、改服务器与面板配置
                 （也可以直接改 TOML 原文）、多套配置档案切换、实时日志、
                 检测并更新 frp 版本。配置和 FrpManager 共用 —— 以前配好的服务器
                 与规则直接就在，不用重录。详见第六节。

三、数据存在哪
  %LOCALAPPDATA%\ServerOpsHelper\
      servers.json    服务器列表
      links.json      常用链接
      vault.json      密码箱
      history.json    访问历史
      settings.json   设置（主题、开关等）
      users.json      登录账号（哈希存储）
      extensions\     你自己加的扩展（每个扩展一个 json，没有就是空文件夹）
      WebView2Data\   内置浏览器的登录态与缓存
      logs\           出错记录（crash-日期.log）

  · FRP 穿透的配置**不在这个目录**，而在 %APPDATA%\FrpManager\
    （profiles\ 下每套配置一个文件夹，state.json 记着 frp 程序路径和当前用哪套）。
    那是 FrpManager 原来的位置，两个程序共用同一份，别单独删。

  · logs\ 是程序**出错时**才写的诊断文件。一般用不到；
    如果哪天界面弹出「操作出错（已拦下）」，照着提示里的路径把它发出来即可定位。
    它只是个文本日志，删掉不影响使用。
  · 用安装包装的话，上面这个文件夹在**安装时就会建好**，装完直接就能看到它；
    卸载**不会删它** —— 里面的密码箱、服务器列表、访问记录都会原样留着。
    （前提是里面有东西。若一直是空的，卸载时会被顺手清掉，这没有影响。）

  · 这是「程序便携 + 数据在用户目录」的组合：程序放哪都行，数据固定在上面这个目录，
    换电脑不会自动带走。要迁移请把整个目录一起拷过去。
  · **想让数据随程序一起走**（真便携）：设一个环境变量 SERVEROPSHELPER_CONFIG_DIR 指向
    你想要的目录（比如程序旁边的 data 文件夹），程序就会把上面的文件都存在那里。
  · 每次保存都会把上一版留成 xxx.json.bak。万一数据写坏了，把 xxx.json.bak 改名成 xxx.json
    就能恢复到上一次保存前的状态。
  · 安装版升级/卸载**都不会删掉上面这个目录**，设置与密码都还在。
  · 密码用 Windows DPAPI 加密（明文前缀标记 DPAPI:），**绑定当前 Windows 账户**，
    换 Windows 用户或换机器后需要重新录入密码。
  · 忘记登录密码：删掉 users.json，重新用 admin / admin123 登录即可（其它配置不受影响）。
  · 想彻底清空：把上面这个目录整个删掉。

四、让智能体接管服务器（MCP）
  这个版本把「已保存的服务器」暴露成一个 MCP 服务。本机的 AI 智能体接上之后，
  就能直接查询和操作这些机器 —— 用的就是你在这里已经存好的服务器，不用重复录一遍。

  1) 两种接入方式，选一种即可

     · stdio（推荐，最省事）
       智能体自己把本程序当子进程拉起来，不需要端口、不需要令牌。
       在「系统设置 → 智能体接入」里点「复制 stdio 配置（推荐）」，
       粘到客户端的 MCP 配置文件里就行。生成的内容长这样：

         {
           "mcpServers": {
             "serveropshelper": {
               "command": "C:\\...\\ServerOpsHelper.exe",
               "args": ["--mcp-stdio"]
             }
           }
         }

     · 本地 HTTP
       适合客户端不支持拉起子进程、或者想复用正在运行的那一份程序。
       在设置里打开「启动本地 MCP 服务（HTTP）」，再点「复制 HTTP 配置」。
       服务只监听 127.0.0.1（局域网访问不到），每个请求都要带访问令牌。
       别把配置连令牌一起发给别人 —— 令牌等于这台机器的操作权限。

  2) 智能体能做什么

     只读（默认就能用）：
       · 列出 / 查询已保存的服务器（名称、地址、系统、标签、备注、最后连接时间）
       · 采集一台机器的实时指标（CPU、内存、磁盘、网络、负载、运行时长）
         CPU 使用率和网络吞吐靠两次采样求差，所以这个调用本身要 1~2 秒；
         内存、磁盘、负载是瞬时值。取不到时会明确返回 null，不会瞎编。
       · 列远程目录、读远程文本文件
         读文件按字节分页（默认每页 64 KiB），智能体会顺着 nextOffset 续读；
         大日志建议改用 grep/tail 之类的命令，省带宽也省上下文。

     变更（需要先在设置里打开「允许智能体执行变更操作」）：
       · 在一台机器上执行 shell 命令
       · 在多台机器上并发执行同一条命令（按标签或指定名单）
       · 通过 SFTP 写入远程文件（覆盖，或追加续写）
       · 在本机与远端之间传文件：upload_file / download_file
         直接流式拷贝，内容不经过对话内容，因此没有大小上限，
         二进制文件、整个目录（递归）都能一次传完；
         指定 overwrite=false 可以避免覆盖已有文件。
         这两个工具会读写本机磁盘，所以同样归入变更类。

  3) 安全边界（建议先看这一段）

     · 服务器密码不会出现在任何返回内容里，智能体拿不到也看不到。
     · 变更操作默认关闭。只读能力不需要授权，能改机器的事必须你亲手打开。
     · 智能体的每一次调用都记进 logs\mcp-audit-日期.log：
       时间、工具、目标机器、命令原文、成功与否、耗时。出问题可回溯。
       （设置页有「打开审计日志目录」按钮，直接跳过去。）
     · 不想用了：关掉 HTTP 开关（stdio 方式删掉客户端配置即可），
       或者点令牌旁边的「重置」换一个，已接入的客户端会立即失效。

五、扩展（给程序加功能）
  不用等新版本：装一个扩展包，就多几条能用的命令。这些命令会出现在服务器详情页顶部的
  「扩展动作」里，智能体也能直接调用。

  1) 装扩展

     · 打开「系统设置 → 扩展」。「推荐扩展」里有三个现成的 —— Nginx 维护、系统巡检、
       日志排查，点「安装」就能用。
     · 别人给的扩展包：点「安装扩展包…」，选 .zip 或 .json 文件。
       zip 里要有一个 extension.json（在根目录或者一层子目录里都行）。

  2) 管扩展

     每个已安装的扩展卡片上有三个按钮：

       停用 / 启用   只是关掉，不删文件。停用后界面和智能体都看不到它的命令
       卸载          删掉它（会先让你确认一次）
       打开文件夹    跳到它的 extension.json，方便自己改

  3) 自己写一个（可选，不是必须）

     「手动创建扩展（高级）」里有一段模板，抄下来改 name 和 command 就行。
     文件放这里：%LOCALAPPDATA%\ServerOpsHelper\extensions\<名字>\extension.json

     几个字段的意思：
       command        要在服务器上执行的命令，可以带 ${参数名} 占位符
       writeAccess    true = 会改动服务器（智能体调用需要你打开「允许变更操作」）；
                      false = 只读命令，智能体不用授权就能调用
       parameters     参数定义；没写 default 的就是必填
       占位符会被替换成**加了引号**的值，所以模板里不要再自己加引号：
         正确：tail -n ${lines} ${path}
         错误：tail -n "${lines}" "${path}"

  4) 几条注意

     · 命令在 Linux 服务器上执行，跟 SSH 终端里敲的一样（sudo 需要免密）。
     · 写错了不会影响程序启动：卡片上会标「加载失败」并给出原因，改好点「刷新」。
     · 扩展是本地的纯文本文件，可以复制给别人、也可以用 AI 生成；
       它不会执行任何下载来的程序，只是把命令发到你选的服务器上。

六、FRP 穿透（内网穿透）
  左侧导航的「FRP 穿透」把 FrpManager 那套管理界面搬进来了。和它**共用同一份配置**：
  以前在 FrpManager 里配好的服务器、规则、frp 目录，这里打开就能看到，不用重录。

  1) 四个页签

     概览       顶部能选模式（frpc 客户端 / frps 服务端）和配置档案；右上角「启动 / 停止」；
                下面显示运行状态、这份配置要连哪台服务器、有几条转发规则，
                以及 FRP 目录是否可用、frp 版本和「安装 / 更新」。

     转发规则   左边是规则表，右边改详情。点「＋ 添加」新建，选中一条改完点「应用并保存」。
                · 类型 tcp / udp 要填「远程端口」
                · 类型 http / https / tcpmux 要填「域名」（多个用逗号隔开，不填远程端口）
                改完立即写进 frpc.toml，不用再点别的保存。

     服务器配置 填服务器地址、端口、Token、传输协议（TCP / KCP / QUIC / WebSocket / WSS）。
                勾上右上角「文本模式」可以直接改 TOML 原文（高级用法）。
                改完点「保存配置」。

     运行日志   实时显示 frpc/frps 的输出，系统消息蓝色、错误红色，可清空。

  2) 要注意的

     · 改完配置或规则，要**停止再启动**才生效（界面上也有这句提示）。
     · 点「启动」前会先自动保存一次表单，所以不会出现"改了没保存、起的是旧配置"。
     · **关闭本程序会停掉正在运行的 frpc/frps**（不停的话它会变成没人管的进程，
       下次也管不了）。要让它长期跑，请用 FrpManager 或做成系统服务。
     · 配置档案可以有多套（按「新建 / 重命名 / 删除」管理），至少保留一套。
     · frp 程序路径可以在概览里改；点「自动定位」会找几个约定位置。
     · frp 程序（frpc.exe / frps.exe）**不随安装包一起装** —— 两个 exe 共 36MB。
       第一次用如果显示"不可用"，点「安装 / 切到稳定版」自动下载（约 20MB，需要能上 GitHub）。
       已经有的机器不用重下：程序会自己找到（组件目录 / 程序目录旁的 frp\ / PATH）。

七、运行要求
  · Windows 10 1809 及以上 / Windows 11，64 位
  · 本包已内置 .NET 9 运行时，**不需要另外安装 .NET**
  · 内置浏览器依赖 Microsoft Edge WebView2 Runtime：
    Win11 与较新的 Win10 已随系统自带。若启动后提示「WebView2 初始化失败」，
    到微软官网安装 Evergreen 版运行时即可：
    https://developer.microsoft.com/microsoft-edge/webview2/

八、注意
  · **v1.9.3 起换了安装程序**（Inno Setup 取代原来的 MSI）。
    以前那个「无法设置文件 …rbf 的文件安全。错误: 5」是 MSI 的回滚机制造成的，
    新版安装程序不走 Windows Installer，**这个错误不会再出现**。
    从旧版升级：直接运行新安装包，向导会问要不要先卸载旧版，选「是」即可
    （卸载不动你的数据）。
  · 装好后日常用桌面/开始菜单的快捷方式启动；装过一次就不用反复运行安装包。
    要卸载/重装，走 Windows「设置 → 应用」最省事。
  · 「重启服务」会操作本机 Windows 服务，需要管理员权限；SSH 连接需要能访问目标主机。
  · 请只在自己的机器或有明确授权的环境里使用。
  · 开了「允许智能体执行变更操作」，等于把这几台机器的命令执行权交给智能体。
    只在你信任的客户端、信任的模型上开；用完不确定就关掉。
